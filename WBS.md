# WBS

## 1. Planning

1.1 meeting team alignment on project idea)

1.2 Define project goals and scope

1.3 Identify stakeholders and user needs

1.4 Review similar systems

1.5 Set up GitLab repository



## 2. Requirements Analysis

2.1 Conduct stakeholder discussions 

2.2 Identify and confirm user needs (C-type requirements)

2.3 Identify key system features and constraints

2.4 Define core problem and solution approach

2.5 Validate requirements with team members



## 3. Document Structure

3.1 Create requirements document outline

3.2 Define section responsibilities 



## 4. Writing – Part A: Vision and Scope

4.1 Write Problem Statement

4.2 Define Vision

4.3 Define Objectives

4.4 Define Success Metrics

4.5 Identify Stakeholders

4.6 Define Target Users (Primary & Secondary)

4.7 Define Scope (In Scope / Out of Scope)

4.8 Write Scope Rationale



## 5. Writing – Part B: Functional Requirements

5.1 Identify core system functionalities

5.2 Write functional requirements (FR-01, FR-02, etc.)

5.3 Define acceptance criteria for each FR (Given-When-Then)

5.4 Assign priority using MoSCoW method

5.5 Review and refine functional requirements



## 6. Writing – Part B: Non-Functional Requirements

6.1 Identify quality attributes (Performance, Usability, Security, etc.)

6.2 Define measurable NFRs with targets

6.3 Define acceptance tests for each NFR

6.4 Ensure requirements are testable and unambiguous

6.5 Review and refine NFRs



## 7. Writing –Constraints, Assumptions and Dependencies

7.1 Identify project constraints (time, team size, APIs)

7.2 Define assumptions about users and system usage

7.3 Identify technical and data dependencies

7.4 Validate consistency with requirements



## 8. Writing –Risks and Acceptance Criteria

8.1 Identify potential risks (technical, data, team)

8.2 Assess likelihood and impact

8.3 Define mitigation strategies

8.4 Define project-level acceptance criteria

8.5 Ensure alignment with success metrics



## 9. Review and Revision

9.1 Internal peer review within team

9.2 Cross-check consistency across sections

9.3 Fix unclear or ambiguous requirements

9.4 Final formatting and proofreading

9.5 Prepare final submission version



## 10. Project Management Artefacts

10.1 Create and maintain key artefacts

10.2 Upload all artefacts to GitLab repository



## 11. Submission

11.1 Final check against marking rubric

11.2 Export document to PDF and submit
